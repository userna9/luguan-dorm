# 吃饭询问的微信提醒（两条路）

> 目标：让室友在**不打开小程序**的情况下也知道"有人问吃什么"。
> 提供两条互补的路：**转发到宿舍群**（零配置、立刻可用）+ **订阅消息**（微信服务通知，需要配模板）。

---

## ⚠️ 前置条件：小程序必须完成微信认证

**未认证的小程序，微信会直接禁用分享/转发**——代码写得再对也没用，点转发会提示「由于小程序未完成认证，分享功能暂时无法使用」。订阅消息同样受影响。

| 能力 | 未认证 | 已认证 |
|---|---|---|
| 转发给好友 / 群 | ❌ | ✅ |
| 分享到朋友圈 | ❌ | ✅ |
| 被微信搜索到 | ❌ | ✅ |
| 订阅消息（服务通知） | ❌ | ✅ |

**认证方法**：mp.weixin.qq.com → 设置 → 基本设置 → 微信认证，**300 元/年**，个人主体也可以认证。

> 另外注意：2023 年 9 月起小程序强制要求 **ICP 备案**，没备案无法发布上线。
> 认证解决"能力受限"，备案解决"能不能上线"，两件事都要做。

**不认证的替代方案**（代码已内置，开箱可用）：

吃饭弹窗底部有一行小字「**转发不了？点这里复制提醒文字**」，点一下会复制：

```
🍚 有人问中午吃什么，打开小程序「乱世诸雄」→ 首页 → 吃饭询问，选一下
```

粘贴到宿舍群即可。不依赖任何认证、不依赖订阅模板。

**再补一个不花认证费的技巧**：让室友在小程序右上角「···」→「**添加到我的小程序**」。
之后从微信首页下拉就能直接进入，比搜索（未认证搜不到）方便得多。

## 为什么不能做「系统通知」（手机通知栏推送）

**小程序没有任何可以主动推送到手机通知栏的 API。** 这是平台沙箱限制，跟认证无关——认证了也不会有。

原因：小程序运行在微信内部，没有独立进程，也不申请通知权限。手机通知栏里那条"微信"的通知，是**微信 App 自己**发的，小程序无权调用。

微信内唯一近似的东西是**订阅消息**，它在用户手机上的实际表现是：

```
微信 → 服务通知 → 一条消息
```

如果用户开了微信的通知权限，**这条消息同样会弹通知栏**，只是显示为"微信"。所以体感上接近系统通知，但：

- 必须先**微信认证**（未认证连这个都没有）
- 一次授权只能发一条（见上文额度池）
- 用户点开才进小程序

**想要真正的系统级推送，只能换载体**：

| 方案 | 成本 | 适合度 |
|---|---|---|
| 独立 App | 高（开发+上架+推送服务） | 宿舍场景完全不值得 |
| 短信 | 需企业资质 + 签名报备 | 太重，而且贵 |
| 微信公众号模板消息 | 需服务号 + 认证 + 用户关注 | 比小程序认证还麻烦 |
| 钉钉/飞书/QQ 群机器人 | 需要宿舍都用同一个平台 | 如果本来就用，这是最省事的 |

对 6 个人的宿舍，性价比排序：**复制提醒文字（0 元） > 认证后订阅消息（300 元/年） > 换平台机器人 > 其他**。

## 先明确技术边界（很重要）

微信小程序**没有**像 App 那样的主动推送。唯一的官方通道是「订阅消息」，也就是聊天列表里的「服务通知」。

| 类型 | 能否用 | 限制 |
|---|---|---|
| **长期订阅** | ❌ 基本不可能 | 仅对政务民生、医疗、交通、金融、教育等**公共服务领域**开放，宿舍类小程序申请不到 |
| **一次性订阅** | ✅ 可以 | **用户每点一次「允许」，只能给他发一条** |

所以本项目用的是「一次性订阅 + 额度池」：

```
用户点「开启微信提醒」→ 授权成功 → 云端 users.subQuota + 1
有人发起询问        → 给 subQuota > 0 的室友各发一条 → 每人 subQuota - 1
```

用户勾选「总是保持以上选择」之后，再点按钮**不会再弹窗**，秒完成 +1，所以"多点几次攒着"是可行的。

---

## 能不能把授权次数设成「无限」？

### 伪造额度：不行

真正的计数在**微信服务器**上。把数据库里 `users.subQuota` 改成 99999 也没用——发送时微信校验的是用户实际授权过多少次，超了照样返回 `43101`。

`subQuota` 只是本地记账，作用是**避免无谓的失败调用**，不是权限来源。

### 近似无限：可以，代码已实现

关键机制：用户第一次授权时如果勾选了「**总是保持以上选择，不再询问**」，之后每次调用 `wx.requestSubscribeMessage` 都**不会弹窗**，直接返回 `accept` 并 +1 次。

所以代码在用户每次点击时顺手补一次额度：

| 触发点 | 效果 |
|---|---|
| 点开「吃饭询问」卡片 | 静默 +1 |
| 点「发起询问」 | 静默 +1 |
| 点某个选项作答 | 静默 +1 |

实现要点：

- `index.js` → `silentTopUpSubscribe()`：只补额度，不弹任何 UI
- `index.js` → `onShow` 里调 `refreshSubSetting()`，用 `wx.getSetting({ withSubscriptions: true })` 缓存"是否勾了总是保持"
- 只有 `subItems[TEMPLATE_ID] === true` 的用户才静默补，**没勾过的用户不会被打扰**
- 5 秒内重复点击只补一次，防止刷太猛

**效果**：一个经常用小程序的人，额度基本永远用不完，相当于无限次。

> ⚠️ 前提仍然是**微信认证**。未认证连授权弹窗都出不来。

## 路一：转发到宿舍群（已可用，零配置）

**怎么用**：打开首页 → 吃饭询问 → 弹窗底部点「**转发到宿舍群**」→ 选宿舍群发送。

群里会收到一张卡片，点开直接落到首页并**自动弹出吃饭询问**，点一下选项就完成作答。

**实现**：

| 位置 | 内容 |
|---|---|
| `pages/index/index.js` → `onShareAppMessage` | 分享标题随当前餐次变化，路径带 `?openMeal=1` |
| `pages/index/index.js` → `onLoad(query)` | 识别 `openMeal=1`，统计拉完后自动打开询问弹窗 |
| `pages/index/index.wxml` | 弹窗底部 `<button open-type="share">` |

> 注意：`open-type="share"` 的按钮只有在页面定义了 `onShareAppMessage` 时才生效。

## 路二：订阅消息（微信服务通知）

### 第 1 步：申请模板

1. 打开 [微信公众平台](https://mp.weixin.qq.com/) → 登录小程序
2. 左侧「**功能 → 订阅消息**」
3. 切到「**公共模板库**」→ 选「**一次性订阅**」
4. 搜「提醒」「待办」「日程」之类，挑一个字段合适的（比如"待办提醒"）
5. 申请 → 通过后进入「**我的模板**」→ 点模板 → **详情**，记下两样东西：
   - **模板 ID**（形如 `abcdef1234567890...`）
   - **字段名**（形如 `thing1`、`time2`、`thing3`）

> ⚠️ 如果左侧根本看不到「订阅消息」入口，说明小程序还没认证，或当前类目不在支持范围——这条路暂时走不通，先用路一。

### 第 2 步：填模板 ID（两处，必须一致）

**① `miniprogram/utils/subscribe.js`**

```js
const TEMPLATE_ID = '你的模板ID'
```

**② `cloudfunctions/mealActions/index.js`**

```js
const TEMPLATE_ID = '你的模板ID'
```

### 第 3 步：按你的模板改字段名

`cloudfunctions/mealActions/index.js` 里的 `buildTemplateData()`：

```js
function buildTemplateData(ask, creatorNickname) {
  return {
    thing1: { value: `${ask.mealType}吃什么`.slice(0, 20) },  // 事项
    thing2: { value: String(creatorNickname || '室友').slice(0, 20) }, // 谁发起的
    time3: { value: formatNow() },                            // 时间
  }
}
```

把 `thing1` / `thing2` / `time3` 换成**你模板详情里的实际字段名**，值的类型也要对：

| 字段类型 | 要求 |
|---|---|
| `thing` | 最多 **20 个字符**，超出会报 `47003` |
| `time` | 格式 `yyyy-MM-dd HH:mm:ss` 或 `yyyy年MM月dd日 HH:mm` |
| `phrase` | 最多 5 个汉字 |
| `number` | 纯数字 |
| `character_string` | 数字+字母，32 位以内 |

### 第 4 步：部署

右键 `cloudfunctions/mealActions` → **上传并部署：云端安装依赖**。

前端改的是 `utils/subscribe.js` 和首页，**重新编译**即可。

### 第 5 步：测试

1. 用**你自己的微信号**打开小程序 → 首页 → 吃饭询问 → 点「开启微信提醒」→ 允许
   - 按钮会变成「开启微信提醒（剩 1 次）」
2. 换**另一个微信号**（室友的）→ 点「发起询问」
3. 你的微信聊天列表里应该出现「**服务通知**」，点开直接进入作答页

> 开发阶段 `MINIPROGRAM_STATE = 'developer'`，通知会跳到**开发版**。
> 体验版改 `'trial'`，正式上线必须改 `'formal'`，否则用户点开是空白/报错。

## 路三：企业微信群机器人（免费，推荐给不认证的情况）

**这是唯一「0 元 + 不需要任何认证 + 真能弹通知」的方案。**

### 为什么公众号走不通

很多人第一反应是「弄个公众号发模板消息」，但这条路对个人开发者基本封死：

| 环节 | 现实 |
|---|---|
| 模板消息权限 | **只有「已认证的服务号」能用**，订阅号没有 |
| 服务号注册 | 需要**营业执照**（企业 / 个体工商户） |
| 个人主体 | 只能注册**订阅号** → 永远没有模板消息权限 |
| 用户关注 | 每个室友都要关注你的公众号 |
| openid 打通 | 小程序和公众号的 openid 不同，要用 unionid，且两者必须绑定在**同一个开放平台账号**下（同样需要企业主体） |

结论：除非你有营业执照，否则公众号这条路走不通。就算有，成本（认证 300 元/年 + 大量开发）也远超宿舍场景。

### 企业微信群机器人怎么做

1. 手机装**企业微信**（个人可免费注册一个"企业"，填宿舍名即可，不需要营业执照、不需要认证）
2. 建一个群，**至少 3 人**（把室友拉进来）
3. 群设置 → **群机器人** → 添加 → 复制 **Webhook 地址**
4. 填到 `cloudfunctions/mealActions/index.js`：

```js
const WECOM_WEBHOOK = 'https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxxxxxx'
```

5. 重新部署 `mealActions`

之后每次发起询问，群里会收到：

```
🍚 中午吃什么？
小明 发起了询问，打开小程序「乱世诸雄」→ 首页 → 吃饭询问，选一下～
@所有人
```

**优点**：0 元、不需要认证、能 @所有人、消息会弹手机通知栏。
**缺点**：室友得装企业微信 App；未认证的企业微信，消息只能在企业微信里看（认证后可以同步到个人微信，但企业微信认证也要 300 元/年）。

> 代码已做容错：没填 Webhook 就跳过，填错也不会影响发起询问本身。

## 常见错误码

| 错误码 | 含义 | 解决 |
|---|---|---|
| `43101` | 用户拒收 / 没有可用的订阅次数 | 让用户重新点「开启微信提醒」；代码已自动把额度清零 |
| `47003` | 模板参数不合法 | 字段名不对，或 `thing` 超过 20 字符 |
| `40003` | openid 无效 | 检查 `users` 集合里的 `_openid` |
| `41030` | 页面路径不存在 | 检查 `NOTIFY_PAGE` 是否写错 |
| 收不到但无报错 | `miniprogramState` 与当前版本不符 | 开发阶段用 `developer` |

## 数据结构变化

`users` 集合新增两个字段（不用手动建，代码会自动写）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `subQuota` | number | 还能被提醒几次（每次授权 +1，每次发送 -1） |
| `subUpdatedAt` | date | 最近一次授权时间 |
