# 宿舍小院：实现与部署

首页「去小院」进入；保留原来的五个底部标签。分支 feature/shared-courtyard。

## 本机预览

未部署新云函数时，页面会提示共养服务未连上。点「本机试玩」后可操作狗狗、花盆、公共树和每日事件。试玩只写本机 storage，带固定提示，不会伪装成多人同步。试玩使用同一套规则，三人事件和六人接力不能单人完成；完整协作可运行 tools/test-courtyard.js 验证。

## 部署负责人操作

1. 云开发控制台新建集合 `courtyard`，权限设为「所有用户不可读写」（只有云函数访问；不要开放前端写入）。
2. 在该集合创建文档 `_id` 为 `shared`。文档内容来自 `docs/courtyard-seed.json`，注意 `_id` 字段保留为 shared。
3. 部署新增云函数 `courtyardActions`（上传并部署：云端安装依赖），超时建议 20 秒。设置环境变量 `COURTYARD_MEMBERS` 为六位室友的 openid，用英文逗号分隔；从 users 集合核对，必须恰好六个且互不重复。未配置时云函数会拒绝共享请求。config.json 包含起名文本安全检查权限。不要部署其他云函数。
4. 登录已在 users 集合保存昵称的账号，打开小院，应显示共养页面、不再显示本机试玩标记。用两个室友账号验证共同喂食记录、花盆归属、重复浇水提示，再由三位室友验证事件接力。
5. 所有验收写入均是真实共享互动。如需测试，用单独开发云环境；不要清空线上 shared 文档。
6. 按分支 + PR 合并后上传新版小程序，选为体验版或走审核发布。仅更新前端不够，新函数和集合都需要先准备好。

## 当前规则

- 上海时间早上 5 点切换宿舍日；服务端时间为准。
- 六位成员由部署负责人通过云函数环境变量维护白名单，同时需要在 users 中设置昵称。陌生账号无法读取或写入共养状态。首次互动时自动登记到小院成员列表。
- 喂饭每人每天 2 次、全院每天 6 次；陪玩每人 3 次；散步每人 2 次。
- 每人认领一盆花；每盆每天最多 3 位不同室友浇水，每人一次。累计 6 次开花，开花后持续保留。
- 公共树每天六位不同成员接力，完成一次开花纪念；每日事件三种任务各一位不同室友完成。
- 起名 1–8 字，最多六个候选名，每人一票可改投，四票同意锁定。云端检查文本。
- 日记保留最近 30 个有互动跨度的宿舍日，相册保留最近 36 条文字纪念卡；目前没有真实合影或截图生成。
- 宠物名字、花的成长、历史纪念会保留，不衰减、不死亡。性格随累计喂饭、陪玩、散步次数呈现贪吃、戏精或黏人倾向。

## 动画与同步

Canvas 2D 像素角色：待机眨眼摇尾、走路、吃饭、追球、睡觉、迎接、叼拖鞋；花叶摆动，浇水水滴，公共树开花后落花。12 帧/秒，DPR 上限 2，切走停止计时器，可手动暂停动画。回到页面会刷新状态；停留期间每 20 秒同步一次共养和回寝状态。收到新增回寝时迎接，全员回寝时睡觉。

云函数用数据库事务更新同一个小院文档，避免多人覆盖；同次请求 ID 去重。网络错误后先刷新确认，不要误以为未写入。没有改旧云函数。

## 验证

`node tools/test-courtyard.js` 检查规则与 Canvas 七种动画绘制；`node --check` 检查 JS；微信开发者工具 `cli preview` 检查真实小程序编译。多人事务和真机性能仍需部署负责人在测试环境验收。
